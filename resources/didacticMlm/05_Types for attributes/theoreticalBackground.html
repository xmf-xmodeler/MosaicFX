LU5 - Types for Attributes

Theoretical Background

Each attribute must specify exactly one type. The type of an attribute determines the range of available slot values and permitted operations. The following data types are included in UML++:

  • Boolean: Used for truth values. Only allows two values: True and False
  • Integer: Used for integers. Only allows numerical characters, may be preceded with a minus sign (-)
  • Float: Used for real numbers. Only allows numerical characters; must include a decimal point (.) with an integer and a fraction part (e.g., 1.23 or 2.0), may be preceded with a minus sign (-)
  • String: Used for text. Allows any sequence of any characters
  • Date: Used for dates. Always requires day, month, and year combination
  • MonetaryValue: Advanced type, used for prices. Consists of one float value and a currency value
  • Currency: Advanced type, used for currencies. Only allows values from predefined list of currencies.

Currency and MonetaryValue can only be selected after the check box "Show all data types" is activated. Some attributes are more restrictive than others. While Boolean attributes only allow for two values, Integer attributes allow any numerical character. String is the least restrictive type available here; it allows for any set of characters whether they are numeric or not. The type chosen for an attribute should always be as restrictive as possible to prohibit erroneous slot values. Example: A class Course has an attribute creditPoints. The type Boolean would be too restrictive, since two values are insufficient to depict credit points. The type String would be too unrestrictive because it allows many values we know to be wrong (e.g., "Any text"). A fitting type here would be Integer.

We may encounter many attributes that can be restricted to a closer set of values than the default types do: height, video resolution, e-mail address, or ISBN for example. To restrict slot values as much as reasonable, it may be beneficial to specify custom types. For the specification of custom types, we have two options: To specify an Enumeration or a Domain-specific Type.

Enumerations specify a custom list of specific values available to a slot. An example might be the traveling class of a flight ticket. Here, we can specify a travelingClassEnum that contains the values EconomyClass, BusinessClass, and FirstClass. In UML-MX, users can then select a slot value per drop down. Enumeration values may not include spaces or pure integers. For help on specifying enumerations, go to the UML++ Introduction in 0.

Up until now, we have used classes as a modularization of information systems, they allow us to partition the large system into smaller more manageable units, so-called modules. Classes may also serve as types for attributes themselves; we call such types domain-specific types. Using classes as attribute types allows for more complex types since a class may include multiple attributes and other properties (like constraints, see 10). An example might be the resolution of a video. The resolution of a video may be assumed not to possess its own identity; an association from a class Video to a class Resolution should thus be omitted (see 3). But the value of a resolution may still be split into the attributes numberOfPixelsX: Integer and numberOfPixelsY: Integer. Domain-specific classes can be chosen as an attribute type by clicking on "Domain-specific type" and then selecting the desired class in the attribute specification dialog. The example model from 4 already contains the domain-specific type Abstract_ISBN.
