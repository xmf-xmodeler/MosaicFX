LU10 - Custom Constraints with XOCL

Theoretical Background

Basically all modeling constructs we encountered so far (types for attributes, multiplicities, etc.) serve to constrain the set of valid model instantiations. In some cases, the restrictions of existing modeling constructs may be insufficient and in order to ensure the integrity of the system it may be required to specify custom constraints.

Constraints are Boolean expressions that are specified for a class and evaluated in every instance of that class. If a constraint fails, i.e., the evaluated expression returns False, a constraint-violation message is shown within the object. You also encounter constraint violations if the multiplicity of an attribute or association is violated.

Example: In an information system for an amusement park, we want to ensure that all customers are taller than 110cm. The height of a person is captured in the attribute heightInCM: Integer. We may then add the following constrain to the class Customer to ensure this: self.heightInCM > 110. The keyword self always refers to the object in which the constraint is evaluated. Any object of the class Customer that fails to meet this constrain shows an error message (e.g., "Customer is not tall enough!").
